工具库：先说明场景，再让人使用

入口是能力库。按内容生产、数据处理、设计生成、办公自动化等场景筛选。每张卡优先展示解决什么问题、输入什么、输出什么，而不是堆工具说明书。

详情页把“看懂”和“试用”放在同一屏

背景说明、封面和可选前后对比解释工具价值；下载、点赞、四维评分与讨论收集反馈。页面可在线预览，也可下载普通文件。发布信息展示可访问地址与状态。

评分不是只有一个星级
维度权重评价内容
实用性30%能不能解决实际问题
易用性25%是否容易上手
稳定性25%运行是否可靠
说明完整20%场景与使用方法是否清楚

各维度为 1–5 分，按权重求和并保留一位小数。一个用户对一个工具保存一份可修改的评分，下载记录单独统计。

现场怎么讲这一页

“先按业务场景找到能力，再看输入和输出是否适合自己的任务。点进详情，不用先下载就能体验 H5；用过之后，把问题留在评分与讨论里，让作者继续完善。”

上传：提交一次，平台接住后续

上传页不只接收压缩包。它同时支持整站文件夹、单文件 / ZIP、可读共享路径，以及已有在线链接。名称和一句话介绍帮助他人发现工具；截图、输入输出与背景说明补足使用上下文。

  1. 识别交付类型

    识别静态站点与普通工具；链接登记走已有地址路径，不重复部署。

  2. 保存完整资源

    站点放入工具目录存档，普通文件保存在对应目录。相对资源与入口必须配套。

  3. 自动发布

    静态站点推送到可访问地址，生成可追踪路径。

  4. 回写并检查状态

    详情页显示地址和状态。部署可能仍在进行，可检查、重发，不必反复创建新工具。

“提交即可发现”不等于已经部署成功，也不表示任意后端服务都能变成静态站点。

需求池：让未解决的问题有结构地留下来

每位登录用户都可以新增需求，写清角色、工作阶段、任务、交付物、耗时、痛点和改进方案。需求池用状态与主题筛选，支持打开需求详情，管理员可以调整处理状态。

真实页面还提供画布缩放、复位、放大画布和侧边详情。已经落地并有关联工具的需求可以进入对应工具，方便从问题回到解决方案。

这一模块的制作思路

将原始需求整理成结构化字段，再把主题、紧急度和处理状态分别映射到颜色、面积、虚实；文字详情保留完整业务信息。可视化用于帮助判断优先级，不替代需求正文。

培训中心：从认识 AI，到交付自己的工具

培训以学习路径组织，不是简单的课程下载列表。学习入口和业务实操分层，独立 H5 可以承载完整操作过程。

业务实操

H5 实操区分“演示链路”和“汇报结论”；工具实操以可复用脚本、桌面工具和上架交付为重点，连接平台内的案例。

进度与有效时长

课程进度、学习等级和团队学习情况帮助了解培训覆盖。页面可见且最近有操作时才发送有效时长，不能把挂着页面的全部时间算成学习。

完成标记和有效学习时长是两种记录，不代表自动评测掌握程度，也不是考试成绩。

我的空间：把使用过的能力留下来

我的工具

聚合用户点赞或下载过的工具，帮助再次找到常用能力；不是把所有上传工具都算成自己的使用记录。

我的收益

对这些去重后的工具，汇总其单次节省时间并换算为小时。该口径是估算，不等于真实累计使用时长或团队财务收益。

我的工作流

用固定条目展示「教材 → 视频生产」等场景，帮助理解空间结构，不是可运行的工作流编排系统。

后台：让课程和平台可以持续维护

培训 H5 管理是一条独立的课程发布链路

填写标题、分类、简介、排序及初始状态，上传完整 ZIP。包内必须有 index.html；发布前检查危险路径、符号链接、服务端脚本和解压体积。管理员可以预览、编辑、替换 H5 包、发布、下架和删除。

  1. 草稿 / 直接发布
  2. 完整 ZIP 校验
  3. 持久化课程目录
  4. 培训中心展示
  5. 登录保护预览

工具站点可自动发布为可访问页面；培训课程在登录保护下运行。两条链路不能混为“所有课程都公开上线”。课程下架后普通用户不可继续访问。

按角色说明权限，展厅内不操作真实账号
角色主要能力
普通用户登录、查看工具与需求、上传工具、参与反馈、学习课程、查看个人空间
管理员贡献看板、账号数据、用户与工具维护、课程管理、需求状态维护
超级管理员受额外保护的最高权限；普通管理员不能对其降权

它是怎么做出来的

先围绕团队交付定义信息，再把页面、数据、文件和发布流程分开组织。下面讲的是作品背后的职责分工，而不是工期表。

  1. 把场景变成字段

    工具记录分类、场景、输入、输出与说明；需求记录角色、阶段、痛点与方案；课程记录状态与入口。结构化之后，才能按业务找能力。

  2. 搭起可阅读的页面

    统一导航与登录状态；工具库、详情、需求、培训、个人空间、看板与管理各司其职。

  3. 保存关系与文件

    账号、资源、反馈与学习活动写入数据；附件与完整站点落在磁盘目录，发布失败也不丢原稿。

  4. 封装发布与权限

    静态站点自动发布并回写状态；登录与角色守住课程与后台边界；上传前先做结构校验。

  5. 写清如何继续运转

    依赖、备份与交接约定写清楚，系统能被下一个人接手。

一句话怎么介绍这个作品

“我把内容团队的工作拆成四件事：发现需求、交付能力、帮助别人学会、观察实际使用。工具库负责复用，培训中心负责传递方法，需求池承接下一轮问题。上传之后的存档与发布由平台接住，同事不必自己处理发布细节。”

作品边界

这是一份本地可体验的功能展厅，不是后台系统的离线克隆。导航、折叠说明和培训 H5 可以直接打开；真实上传、评分、账号维护与数据统计仍属于原平台服务。

  • 展厅覆盖：工具库、详情、上传入口、需求池、培训路径、我的空间、贡献看板与管理能力。
